# PhotoMap アーキテクチャ詳細設計書

最終更新: 2026-06-01

## 1. 目的

本リファクタリングは、Next.js 固有の UI とドメインロジック・API 呼び出しを分離し、以下を実現することを目的とする。

- **移植性**: React Native / Electron 等へ UI を差し替えても、`features/*/api` をそのまま再利用できる
- **テスタビリティ**: fetch と状態管理を hooks / api 層に集約し、UI は表示に専念
- **保守性**: 重複していた `deletePhoto` や tags fetch を共通化

## 2. レイヤ構成

```
┌─────────────────────────────────────────────────────────┐
│  app/                    … ルーティングのみ（薄い page）   │
├─────────────────────────────────────────────────────────┤
│  components/             … Presentational UI             │
│  shared/ui/ (将来)       … Nav, Lightbox 等の共通 UI      │
├─────────────────────────────────────────────────────────┤
│  features/*/hooks/       … 状態 + 副作用（React 専用）     │
│  features/*/lib/         … 純粋関数（フレームワーク非依存） │
├─────────────────────────────────────────────────────────┤
│  features/*/api/         … HTTP クライアント（移植可能）   │
│  shared/api/http.ts      … fetch ラッパー                 │
├─────────────────────────────────────────────────────────┤
│  app/api/                … Route Handlers（サーバー HTTP） │
│  lib/ (server)           … auth, supabase, geocode 等    │
└─────────────────────────────────────────────────────────┘
```

### 依存の方向

- `components` → `features/*/hooks` → `features/*/api` → `shared/api`
- `app/api` → `lib/`（サーバー専用）
- **禁止**: `features/*/api` から `components` を import しない

## 4. API 契約（クライアント api 層）

クライアントは **`/api/*` への HTTP** のみに依存。将来ベース URL を差し替え可能。

| 関数 | メソッド | パス |
|------|----------|------|
| `fetchMyProfile` | GET | `/api/me/profile` |
| `updateMyProfile` | PATCH | `/api/me/profile` |
| `deleteMyAccount` | DELETE | `/api/me/account` |
| `fetchMyPhotos` | GET | `/api/me/photos` |
| `deletePhoto` | DELETE | `/api/photos/:id` |
| `fetchCustomTags` | GET | `/api/me/tags` |
| `createCustomTag` | POST | `/api/me/tags` |
| `deleteCustomTag` | DELETE | `/api/me/tags/:id` |
| `fetchSpotGallery` | GET | `/api/spots/:id` + `/photos` |
| `fetchPhotosInBounds` | GET | `/api/photos/in-bounds` |
| `fetchPhotosBySpots` | GET | `/api/photos/by-spots` |
| `uploadPhotoViaStorage` | POST+PUT+POST | prepare / Storage / complete |
| `reverseGeocode` | GET | `/api/geocode/reverse` |

  └─ profileStats       → buildFavoriteSpots()  [純粋関数]
```

  ├─ uploadPhotoViaStorage()
  └─ Upload* components → presentational
```

### server/services 構成

API Route は `{ auth → service → response }` の薄い adapter。

| サービス | 担当 |
|----------|------|
| `profileService` | プロフィール取得・更新 |
| `photosService` | 自分の写真一覧・削除・公開設定 |
| `spotsService` | バウンド内スポット一覧 |
| `tagsService` | ユーザータグ CRUD |
| `authService` | 登録・パスワードリセット |

### shared/ui 構成

| パス | 内容 |
|------|------|
| `shared/ui/Nav/` | TopNav, BottomNav, アイコン, nav.css |
| `shared/ui/Photo/` | PhotoLightbox |
| `shared/ui/Theme/` | ThemeProvider |

既存 import `@/components/Nav/*` 等は re-export によりそのまま動作。新規コードでは `@/shared/ui/*` を推奨。

## 7. 移行時の注意

- 既存 import `@/lib/spotsBoundsCache`, `@/lib/uploadPhotoClient` は re-export により **そのまま動作**
- 型は `@/components/Me/types`, `@/components/Gallery/types` から feature 型へ re-export
- 新規コードでは `@/features/*` を直接 import すること
