# アプリ仕様書：フォトマップ（Photo Map）

**バージョン：** 1.2  
**作成日：** 2026年4月28日  
**対象プラットフォーム：** Web / Android / iOS（PWA）

---

## 1. プロジェクト概要

画像をアップロードすると、画像に紐付く位置情報を自動取得し、地図上に吹き出し（マーカー）として表示するサービス。同一スポットの画像はまとめて表示し、地図のズームレベルに応じて市・県・地方・国・世界単位で表示を切り替える。

### 4.2 画像アップロード

#### 位置情報取得フロー

```
画像アップロード
    ↓
EXIF の GPS 情報を確認
    ├─ GPS あり → 緯度・経度を取得
    │               ↓
    │           Nominatim で逆ジオコーディング（座標→地名）
    └─ GPS なし → ユーザーに通知し、手動で場所を入力するよう促す
```

> GPS 情報のない画像はアップロード自体は可能だが、地図上に表示するには手動での場所入力が必要。

#### スポット判定ロジック（同一場所の統合）

1. **地名・施設名による判定**  
   Nominatim が返すスポット名・施設名を正規化し、同一名称であれば同一スポットとみなす。

2. **座標による判定（近似値）**  
   スポット名が取得できない場合、または同名スポットが複数座標に存在する場合は半径 **50m 以内** を同一スポットとして統合し、重心座標を代表座標とする。

3. **ユーザーによる手動統合・分割**  
   スポット管理画面から、スポットの結合・分割が可能。

---

### 4.3 地図表示

#### ズームレベルと表示モード

| 表示モード | ズームレベル目安 | 表示単位 |
|-----------|----------------|---------|
| 世界 | 1〜3 | 国別クラスタ |
| 国 | 4〜6 | 地方別クラスタ |
| 地方 | 7〜9 | 県別クラスタ |
| 県 | 10〜12 | 市別クラスタ |
| 市 | 13〜15 | 個別スポット |
| スポット | 16〜 | スポット詳細 |

表示モードはズームに連動して自動切替するほか、UI 上のボタンで手動切替も可能。

#### クラスタリング

- 同一スポットの吹き出しは1つにまとめ、件数バッジを表示する。
- ズームが粗い場合は地理的近傍のスポットを `Leaflet.markercluster` でクラスタリングして表示する。

#### マーカー（吹き出し）仕様

- 代表画像のサムネイルを吹き出しに表示。
- 複数画像の場合は枚数バッジ（例：「+5」）を表示。
- クリック / タップでスポット詳細パネルを表示。

---

### 4.4 スポット詳細・画像一覧

- スポット名、住所、座標を表示。
- 紐付く全画像をグリッド形式で表示。
- 画像クリックで拡大表示（ライトボックス）。
- 各画像に投稿者・投稿日時・公開設定を表示。

---

### 4.5 公開設定

| 設定 | 説明 |
|------|------|
| 公開 | 全ユーザーが地図上で閲覧可能 |
| 非公開 | 投稿者本人のみ閲覧可能 |

- アップロード時にデフォルト設定を選択可能。
- 投稿後もマイページから変更可能。

---

### 4.6 検索・フィルター

- スポット名・地名でのキーワード検索。
- 投稿日時の範囲フィルター。
- 自分の投稿のみ表示フィルター。

## 6. データモデル

### users テーブル

| カラム | 型 | 説明 |
|-------|----|------|
| id | UUID | PK |
| email | VARCHAR | メールアドレス |
| display_name | VARCHAR | 表示名 |
| avatar_url | TEXT | アイコン URL |
| created_at | TIMESTAMP | 作成日時 |

### spots テーブル（スポット）

| カラム | 型 | 説明 |
|-------|----|------|
| id | UUID | PK |
| name | VARCHAR | スポット名（施設名・地名） |
| location | GEOMETRY(Point, 4326) | 代表座標（PostGIS） |
| address | TEXT | 住所 |
| created_at | TIMESTAMP | 作成日時 |

### photos テーブル（画像）

| カラム | 型 | 説明 |
|-------|----|------|
| id | UUID | PK |
| user_id | UUID | FK → users.id |
| spot_id | UUID | FK → spots.id |
| storage_url | TEXT | ストレージ URL |
| thumbnail_url | TEXT | サムネイル URL |
| is_public | BOOLEAN | 公開フラグ |
| taken_at | TIMESTAMP | 撮影日時 |
| created_at | TIMESTAMP | 投稿日時 |
| exif_lat | DOUBLE | EXIF 緯度（raw） |
| exif_lng | DOUBLE | EXIF 経度（raw） |

## 8. 非機能要件

| 項目 | 要件 |
|------|------|
| レスポンス | 地図マーカー表示：2秒以内（通常回線） |

## 9. 広告・収益化

### 9.1 広告ネットワーク

| サービス | 種別 | 概要 |
|---------|------|------|
| **Google AdSense** | ディスプレイ広告 | 審査制。クリック・表示回数に応じた収益。Next.js との相性良好。 |
| **Amazonアソシエイト** | アフィリエイト | カメラ・旅行グッズなど写真系ユーザーとの親和性が高い。成果報酬型。 |
| **A8.net / バリューコマース** | アフィリエイト | 国内案件豊富。旅行・宿泊系の広告との相性が良い。 |

### 9.2 広告掲載箇所

| 画面 | 掲載箇所 | 理由 |
|------|---------|------|
| スポット詳細 `/spot/[id]` | 画像一覧の下部 | ユーザーが最も滞在する画面。UX を損ないにくい。 |
| マイページ `/me` | 投稿一覧の間 | 定期的に訪問する画面で表示回数を稼ぎやすい。 |
| アップロード完了画面 | 完了メッセージの下 | 操作完了後で広告への抵抗が少ない。 |
| **地図画面 `/`** | **掲載しない** | 操作の妨げになるため除外。 |

### 9.3 実装方針（Google AdSense）

`next/script` を使って AdSense スクリプトを非同期で読み込む。

```tsx
// app/layout.tsx
import Script from 'next/script'

<Script
  async
  src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-XXXXXXXXXXXXXXXX"
  strategy="afterInteractive"
  crossOrigin="anonymous"
/>
```

広告ユニットは再利用可能なコンポーネントとして実装する。

```tsx
// components/AdBanner.tsx
'use client'
import { useEffect } from 'react'

export default function AdBanner() {
  useEffect(() => {
    (window.adsbygoogle = window.adsbygoogle || []).push({})
  }, [])

  return (
    <ins className="adsbygoogle"
      style={{ display: 'block' }}
      data-ad-client="ca-pub-XXXXXXXXXXXXXXXX"
      data-ad-slot="XXXXXXXXXX"
      data-ad-format="auto"
      data-full-width-responsive="true"
    />
  )
}
```

### 9.4 注意事項

- **Vercel Hobby プランは商用利用禁止**のため、広告掲載と同時に Vercel Pro（$20/月）への移行が必須。
- Google AdSense の審査はコンテンツ量・オリジナリティが必要。リリース後、ある程度投稿が蓄積してから申請することを推奨。
- プライバシーポリシーページの設置が AdSense 審査の要件。
- PWA（iOS Safari）では一部広告フォーマットの表示が制限される場合がある。
